# 台指期開盤價基準監控系統

自動監控台指期價格變化，以**開盤價為基準點**計算漲跌幅，透過 Telegram 發送即時警報。

## 📋 功能特色

- **即時價格監控**：每 3 秒抓取台指期最新成交價
- **開盤價基準**：以每個交易時段的開盤價為基準點計算漲跌幅
- **雙向通知**：同時監控從開盤價算起的上漲和下跌
- **自動開盤檢測**：日盤08:45、夜盤15:00自動設定開盤價基準
- **階梯式通知**：漲/跌 500 點後開始通知，之後每 100 點通知一次
- **交易時段獨立**：日盤和夜盤各自獨立計算，互不影響
- **週一自動重啟**：每週一 08:30 自動重置，清空週末資料
- **資料庫記錄**：所有訊號自動儲存到資料庫
- **Web 介面**：提供健康檢查、訊號記錄查詢等功能

## 🎯 監控策略：開盤價基準機制

### 交易時段概念
```
日盤 08:45 開盤 → 設定開盤價為基準點 → 監控到 13:45
夜盤 15:00 開盤 → 重新設定開盤價為基準點 → 監控到 05:00
```

### 實際運作範例
```
日盤 08:45 開盤價：22,000
  ↓
10:30 現價：22,500 → 🚀「從開盤價上漲 500 點」
11:00 現價：22,600 → 🚀「從開盤價上漲 600 點」
12:00 現價：21,400 → ⚠️「從開盤價下跌 600 點」
13:45 日盤結束

夜盤 15:00 開盤價：21,400（= 日盤收盤價）
  ↓ 重新設定基準點，清空通知記錄
17:00 現價：21,900 → 🚀「從開盤價上漲 500 點」
18:00 現價：20,900 → ⚠️「從開盤價下跌 500 點」
```

### 通知規則
- **開始通知門檻**：從開盤價漲/跌 500 點
- **通知間隔**：每 100 點通知一次
- **級距概念**：500、600、700、800... 每個級距只通知一次
- **雙向監控**：同時處理上漲和下跌，互不干擾

### 週一自動重啟
```
每週一 08:30  🌅 自動重置（清空週末資料）
  ↓ 清空歷史資料和通知記錄
  ↓ 等待日盤 08:45 開盤
08:45  ✅ 設定新的開盤價基準點
  ↓ 開始監控新的一週
```

## 🔧 系統架構

### 核心組件

1. **SessionMonitor**：交易時段監控器
   - **開盤檢測**：自動檢測日盤08:45、夜盤15:00開盤時間
   - **基準點設定**：以開盤價為基準點計算漲跌幅
   - **雙向監控**：同時處理上漲和下跌通知

2. **資料庫模型**
   - `SignalLog`：訊號記錄表
   - `Parameters`：參數設定表

   - `/`：服務狀態

   - `/heartbeat`：心跳監控
   - `/signals`：訊號記錄查詢
   - `/stats`：統計資料

## 📝 技術細節

### 資料處理流程

1. 每 3 秒抓取最新價格
2. 將 tick 資料重採樣為 5 分鐘 K 棒
3. **開盤檢測**：檢測是否為開盤時間
4. **基準點設定**：開盤時自動設定開盤價為基準點
5. **漲跌計算**：計算現價與開盤價的差異
6. **通知判斷**：判斷是否達到通知門檻
7. 記錄訊號到資料庫

### 開盤檢測機制

```python
# 檢查是否為開盤時間
is_day_open = (current_hour == 8 and 45 <= current_minute <= 50)
is_night_open = (current_hour == 15 and 0 <= current_minute <= 5)

# 開盤時設定基準點為開盤價
if (is_day_open or is_night_open) and not self.is_session_started:
    self.session_open_price = current_price
    self.session_type = "日盤" if is_day_open else "夜盤"
    self.is_session_started = True
```

### 漲跌計算邏輯

```python
# 計算從開盤價開始的變化
change = current_price - self.session_open_price

# 判斷是上漲還是下跌
if change > 0:
    signal_type = f"從開盤價上漲 {current_level} 點"
else:
    signal_type = f"從開盤價下跌 {current_level} 點"
```

### 防重複通知機制

```python
# 建立通知標識（區分上漲和下跌）
if change > 0:
    level_key = f"up_{current_level}"
else:
    level_key = f"down_{current_level}"

# 檢查是否已通知過
if level_key not in self.notified_levels:
    self.notified_levels.add(level_key)
    # 發送通知
```

## 🛡️ 容錯機制

- **資料庫備援**：連線失敗時自動使用本地 SQLite
- **參數備份**：儲存失敗時備份到本地 JSON 檔案
- **價格抓取**：失敗時自動重試，不中斷監控
- **開盤檢測**：確保每個交易時段都有正確的基準點
- **週一重啟**：清空週末資料，避免跨週計算錯誤
- **Keep-alive**：每 5 分鐘自動喚醒，防止服務休眠

## 🎯 設計理念

這個系統專為**交易時段監控**而設計：

1. **符合交易習慣**：以開盤價為基準點，符合一般交易者的思維
2. **時段獨立性**：日盤和夜盤各自獨立，不會互相干擾
3. **即時性**：開盤後立即開始監控，無需等待暖機
4. **準確性**：避免跨時段計算錯誤，確保每個通知都有意義
